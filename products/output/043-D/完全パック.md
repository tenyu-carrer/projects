# 043-D｜Xの投稿をAIで作る方法

**状態：初稿／投稿づくりの流れ図・投稿表CSV付き。実際の投稿・API接続・反応は未検証**  
対象：Xで発信を始めたい、または毎日の投稿を楽にしたい初心者｜所要：約3〜5時間（1週間分の準備まで）｜更新日：2026-10-31  
前提：042のThreads運用（型と事実確認の考え方）、061のブログ記事（先に読んでも後でもよい）。追加課金、有料API、素材購入は行いません。

## 1｜到達点と完成物

この講座のゴールは、**ブログや日々の気づきを素材に、1投稿1メッセージの短い投稿を1週間分作り、事実と言い過ぎを点検してから出せるようにする**ことです。

完成物は、①設計シート、②素材のリスト、③投稿の下書き（1週間分）、④元の素材との対応表、⑤事実の確認記録、⑥返信への対応の方針、⑦公開前チェック記録の7点です。

付属見本は、架空のアカウントが1本のブログ記事から5本の投稿を作る流れ図と投稿表です。実際の投稿や反応の数字はありません。

進め方の目安：1日目に素材集めと下書き、2日目に事実と言い過ぎの点検、3日目に予約。

**完成条件：** 全投稿が1投稿1メッセージで文字数の上限に収まり、元の素材にない数字や約束がなく、人の確認の印がある。

## 2｜この講座で使う言葉

- **X**：短い文章を中心にしたSNS（旧Twitter）。
- **ポスト**：Xの1つの投稿。
- **スレッド**：つながった複数の投稿。
- **リポスト・引用**：他人の投稿を共有すること。引用は自分のコメントを付けて共有すること。
- **予約投稿**：日時を決めて、あとから出る投稿。
- **X API**：プログラムからXを操作するための公式の入口。使える機能や料金の条件は、公式の開発者向け資料で確認します。

## 3｜1投稿1メッセージ

Xでは、短い文章で読まれます。1つの投稿に言いたいことを詰め込むと、どれも伝わりません。**いちばん大事なことを1つだけ**残します。

```text
投稿の下書き【】を、全角140字以内に縮めて3案。いちばん大事なことを1つだけ残して。
```

文字数の数え方や上限は、アカウントの種類や設定で変わることがあるため、投稿画面で確認します。この講座では、全角140字を目安にします。

## 4｜素材から投稿を作る

毎日ゼロから考えると続きません。ブログ記事、動画、日々の気づきなど、すでにある素材から投稿を作ります。1本のブログ記事から、5本前後の投稿が作れることもあります。

```text
ブログ記事【】から、Xの投稿を5本作って。1投稿1メッセージ、全角140字以内。記事のどの段落から取ったかを書き、記事にない数字は使わないで。
```

**元の素材との対応を記録する**のがポイントです。短くするほど、元の内容から言い過ぎたり、意味がずれたりしやすいからです。

## 5｜型を変える

同じ型が続かないように、いくつかの型を回します。

- **気づき**：「〜して分かったのは、〜でした」
- **手順**：「〜するときは、①〜②〜③〜」
- **数字**：実際に測った数字だけ
- **問いかけ**：読む人の経験を聞く
- **案内**：記事や動画へのリンク（毎回は付けない）

```text
投稿の下書き5本【】を点検して、同じ書き出し・同じ締め・同じハッシュタグが続いている所を指摘して、入れ替え案を出して。
```

## 6｜事実と言い過ぎの点検

短い文章は、条件や例外が抜けやすく、言い過ぎになりがちです。

- 「AIで家計簿が楽になる」→「私の場合、入力の時間が半分くらいになりました」（自分の体験の範囲に）
- 元の記事に「3か月で」とあるなら、投稿でも「3か月で」を残す

```text
投稿の下書き【】の中で、事実の確認が必要な部分（数字・体験・サービスの機能・ニュース）を抜き出して、確認先の候補を付けて。
```

ニュースや他人の発言を紹介する場合は、元の情報を自分で確認し、誤解させる切り取り方をしません。

```text
投稿の下書き【】が、ニュースや他人の発言を誤解させる言い方になっていないか点検して。元の情報と違う点を指摘して。
```

## 7｜長い話はスレッドに

1投稿に入らない話は、スレッドに分けます。1本目だけで興味が持てるようにして、2本目以降で詳しく説明します。

```text
長い話【】を、つながった複数の投稿に分けて。1本目だけで興味が持てるようにして、各投稿は140字以内に。
```

## 8｜予約と自動化のルール

Xには投稿を予約する機能があります（使える条件や画面は変わることがあります）。プログラムで自動投稿する場合は、X APIを使いますが、使える機能や料金の条件は公式の開発者向け資料で確認します。また、Xには自動化についてのルールがあり、同じ内容を何度も投稿する、たくさんのアカウントで同じことをする、自動で大量に返信やいいねをする、といった使い方は禁止されています。

自動化する場合も、041・042と同じく：

- 確認の印がない投稿は出さない
- 同じ文章を続けて出さない
- 鍵（トークン）を他人に見せない
- 止める方法を決めておく

## 9｜返信と言い争いを避ける

Xでは、知らない人から返信や引用が来ることがあります。返事は人がします。意見が違う返信にも、言い争いにならない言い方で答えるか、答えないことを選びます。

```text
もらった返信【】への返事を2案。相手の意見を受け止め、言い争いにならない言い方で。
```

悪口や個人への攻撃には反応せず、必要ならブロックや報告の機能を使います。

## 10｜権利と配慮

- 他人の投稿の文章や画像を、自分のもののように使わない（共有する機能を使う）
- 画像を付ける場合は、自分で撮った・作ったもの、または使ってよい条件のものだけ
- 人の写真を載せるときは本人の許可を取る
- ニュースの画像やスクリーンショットを無断で使わない

## 11｜プロフィールと固定する投稿

投稿を読んで興味を持った人は、プロフィールを見に来ます。プロフィールで「何について書く人か」が分かると、続けて読んでもらいやすくなります。

- 1行目に、何について発信しているかを書く
- 実績を書くなら、確かめられる事実だけにする（「〇万円稼いだ」など確かめられない数字は書かない）
- 固定する投稿（プロフィールのいちばん上に表示する投稿）には、自己紹介や、いちばん役に立った投稿を選ぶ

```text
アカウントのテーマ【】と、これまでの投稿【】から、プロフィール文を2案作って。1行目で何について発信しているかが分かるようにし、確かめられない実績は書かないで。
```

## 12｜素材がないときのネタ帳

ブログや動画がない日も、日々の気づきが素材になります。スマホのメモに、気づいたことを1行ずつためておきます。

- うまくいったこと・いかなかったこと
- 人から聞かれた質問
- 本や記事を読んで考えたこと（文章を写さず、自分の考えを書く）

```text
ネタ帳のメモ【1行ずつ】から、Xの投稿の下書きを5本作って。各メモの内容だけを使い、足りない情報を作らないで。型（気づき・手順・問いかけ）を偏らせないで。
```

## 13｜反応の読み方

1週間たったら、投稿ごとの表示・いいね・返信・リンクのクリックを見ます。数字が少ないうちは決めつけず、型ごとにまとめて比べます。リンクのクリックは、案内の投稿がどれだけ記事につながったかの目安になります。変えるのは1つだけにします。

## 14｜見本で通し練習：記事から1本作るまで

付属の `043-x-posts.csv` の1行目を例にします。

1. **素材**：架空のブログ記事「AIで家計簿をつけ始めて3か月で分かったこと」の第2段落。
2. **1つに絞る**：「レシートを写真で撮ってAIに読ませると、入力の手間が減った」。
3. **下書き**：「家計簿、レシートを撮ってAIに読ませるようにしたら、手で打つのがほぼなくなりました。3か月続いたのはこれのおかげ。」（全角60字前後）
4. **事実の確認**：「3か月」は記事にある数字。「ほぼなくなりました」は自分の体験の範囲の言い方。
5. **リンク**：この投稿には付けない（5本目の案内の投稿でだけ付ける）。
6. **qa**：全文を読んで印を付け、予約します。

## 15｜よくある質問

**Q. 毎日たくさん投稿しないと伸びませんか？**  
A. 本数より、1投稿ごとの中身と、続けられることが大切です。素材から作る仕組みがあれば、無理なく続けられます。

**Q. ハッシュタグはたくさん付けたほうがいいですか？**  
A. 付けすぎると読みにくくなります。内容に合うものを1〜2個にするのがおすすめです。

**Q. AIで作った投稿だと書いたほうがいいですか？**  
A. 文章の下書きにAIを使うこと自体は珍しくありませんが、内容の責任は自分にあります。AIで作った画像を本物の写真のように見せる場合など、誤解を招くおそれがあるときは、AIで作ったことを書きます。

## 16｜アカウントを守る

Xは知らない人とのやり取りが多いSNSです。次の点を最初に設定・確認しておきます。

- 二段階認証を設定し、パスワードを他人に教えない
- 「アカウントが停止されます」などのメッセージのリンクを、確かめずに開かない
- 位置情報や、住んでいる場所が分かる写真を投稿しない
- しつこい返信や攻撃には反応せず、ブロック・ミュート・報告の機能を使う
- 自動化のために外部のサービスにアカウントをつなぐ場合は、そのサービスが信頼できるか、何の権限を渡すのかを確認する

```text
外部のサービス【名前と説明】にXのアカウントをつなぐ前に確認するリストを作って。渡す権限、運営者、解除の方法、データの扱い。
```

## 17｜自動化と収益化（第3段階）

- **固定する作業**：素材→5本の下書き→縮める→重複の点検→事実の抜き出し→誤解の点検→スレッド分け→反応の整理。Cの8プロンプトを順に使います。
- **人がやる作業**：事実の確認、全文の読み直し、返信への対応。
- **お金につなげる場合**：Xで役立つ投稿を続け、ブログやnote、講座などへ案内する形が考えられます。案内の投稿は全体の一部にとどめます。

フォロワー数・売上を保証しない教材です。

## 18｜課題（3段階）

1. **練習**：自分の書いた文章から、140字以内の投稿を3案作る（合格：1投稿1メッセージ）
2. **実用品**：1つの素材から5本の投稿と対応表を作る（合格：元にない数字や約束がない）
3. **公開想定**：1週間分を予約し、返信の方針と公開前チェックをそろえる（合格：全項目に印と確認日）

## 19｜よくある失敗と直し方

1. **1投稿に詰め込みすぎ**：1つだけ残す。
2. **元の記事にない数字を足す**：対応表で確認する。
3. **条件が抜けて言い過ぎ**：自分の体験の範囲の言い方に直す。
4. **毎回リンクを付ける**：役立つ中身だけの投稿を多めにする。
5. **同じ書き出しが続く**：型を回す。
6. **ハッシュタグが多すぎる**：1〜2個にする。
7. **ニュースを誤解させる切り取り**：元の情報を確認する。
8. **他人の画像を無断で使う**：共有する機能を使う。
9. **返信で言い争う**：受け止める言い方にするか、答えない。
10. **同じ内容を何度も自動投稿**：自動化のルールを守る。
11. **鍵を他人に見せる**：見せない、公開しない。
12. **確認せずに予約**：qaの印がないものは出さない。
