# 026-D｜AIで字幕・テロップを自動作成する方法

**状態：初稿／SRT・WebVTT・校正台帳付き。実音声・外部AI・実プレイヤー読込は未検証**  
対象：自動文字起こしを安全に校正し、字幕ファイルへ整えたい初心者｜所要：約4〜8時間｜更新日：2026-10-23  
前提：原音または確認可能な台本を用意する。追加課金、有料API、素材購入は行いません。

## 1｜到達点と完成物

本講座では、自動字幕を「生成できたら完成」にせず、原音、台本、一次資料と照合し、タイムコード、話者、重要音、改行、表示位置、ファイル形式、実再生を検品します。完成物は、①原音・素材台帳、②逐語文字起こし、③校正台帳、④確定字幕、⑤SRT、⑥WebVTT、⑦トランスクリプト、⑧表示確認記録です。

付属SRTとWebVTTは、架空の18秒原稿を手作業で5キューにした教材です。音声認識の結果ではなく、実音声と同期していません。数字、否定、日付、単位、重要音の確認方法と形式差を学ぶための見本であり、すべてのプレイヤー・編集ソフトへの読み込みを保証しません。

**完成条件：** 内容、時刻、形式、表示を別々に検査し、原音確認済みと未検証を区別して記録できる。

## 2｜字幕・テロップ・トランスクリプトを分ける

字幕は音声と同期する文字で、発話に加えて理解に必要な音を含む場合があります。テロップは見出し、強調、補足等の画面内文字で、発話をそのまま写すとは限りません。トランスクリプトは時間に縛られず内容を読むための文書で、重要な視覚情報を説明することもあります。

三つを混同すると、自動字幕を装飾テロップへ変えた際に否定や条件が消えたり、字幕ファイルがあるのに全文を読みたい人へ十分な代替がなかったりします。目的、対象者、公開媒体、別トラックか焼き込みか、必要言語を最初に決めます。

```text
動画の目的【】、視聴者【】、公開媒体【】から、字幕、強調テロップ、トランスクリプトの役割を分ける。
各成果物に含める情報、含めない情報、確認者、完成条件を表にする。
```

## 3｜原音・台本・素材を保全する

元動画、元音声、収録台本、固有名詞一覧、商品・制度等の一次資料を用意します。元ファイルは上書きせず、版と収録日時を記録します。音質が悪い、複数人が重なる、方言・専門語がある等、自動認識が難しい条件も先に記録します。

外部AIへ音声を送る前に、人物同意、個人情報、顧客情報、機密、保存期間、学習利用、共有範囲、削除方法を確認します。許可のない会議、相談、顧客通話を便宜だけで送信しません。必要ならローカル処理、匿名化、対象部分の切り出しを検討します。

```text
素材一覧【】を、所有者、話者同意、個人情報、機密、送信可否、保存、学習利用、削除、代替方法、確認日へ整理。不明は送信可にしない。
```

## 4｜自動文字起こしは下書きとして保存する

使用ツール、モデルまたは機能名、言語設定、辞書、入力ファイル、処理日、出力形式を記録します。自動出力は原文の代わりにせず、未修正の版として保存します。無音区間の削除、話者分離、句読点補完等が自動で行われたかも確認します。

```text
自動文字起こし【】について、欠落、追加、置換、順序、話者、時刻、非発話音の疑いをキュー単位で分類する。
正解を推測せず、原音を聞く必要がある箇所へ優先度を付ける。
```

信頼度スコアがあっても正しさの保証ではありません。高スコアの数字や否定が間違うこともあります。低スコアだけを聞くのではなく、全文を原音と照合する工程を残します。

## 5｜意味を反転させる箇所を先に校正する

数字、日付、時刻、金額、単位、割合、否定、条件、固有名詞、専門語、URL、連絡先は、誤りの影響が大きい箇所です。「採用しません」が「採用します」になれば一文字以上の意味差があります。滑らかな文章へ整える前に、これらを原音と一次資料で確定します。

```text
原文【】と字幕案【】を比較し、数字、日付、時刻、金額、単位、否定、条件、固有名詞、専門語、URLを抽出。
原音、台本、一次資料のどれで確認したか、未確認なら停止理由を記録する。
```

聞き取れない語を文脈から勝手に補いません。`[聞き取り不明]`等の内部マークを使い、話者・監修者へ確認します。公開版に不明箇所を残せない内容なら、再収録または該当区間の削除を検討します。

## 6｜話者と重要音を扱う

話者が変わる場面では、誰の発言か理解に必要なら名前または役割を示します。声だけで本人を推測せず、台本、収録記録、本人確認を使います。匿名性が必要な場合は「話者A」等を一貫して使います。

ドア音、警報、笑い、音楽の開始、通知音等が内容理解に必要なら字幕へ含めます。すべての環境音を書き起こすのではなく、映像の意味や話者の反応を理解するために必要か判断します。

```text
音声メモ【】から話者交代と重要な非発話音の候補を抽出。
各候補にタイムコード、確認根拠、表示しない場合に失われる意味を付ける。人物名は推測しない。
```

## 7｜キュー分割とタイミング

一つのキューは意味のまとまりで分け、助詞と名詞、修飾語と被修飾語等を不自然に切らないようにします。発話より早く答えを出したり、次の場面まで残したりしません。話者交代、場面転換、画面文字との競合を見ながら開始・終了を調整します。

```text
確定原稿【】と粗い時刻【】からキュー分割案。
各キューに開始、終了、文、分割理由、話者、重要音、画面競合を付ける。最終時刻は波形と実再生で人が確定する。
```

読み速度には対象者、言語、内容、画面サイズの差があります。固定の文字数だけで合否を決めず、短縮して意味が落ちないか、表示時間を延ばせるか、実際に読み切れるかを試します。子ども、第二言語学習者、認知負荷の高い内容では余裕を持たせます。

## 8｜改行、句読点、表記統一

改行は文法と意味のまとまりを保ち、上下行の長さを極端に偏らせません。ただし再生環境が自動折返しすることもあるため、手動改行の結果を実プレイヤーで確認します。句読点は読みやすさと話者の意図を支える範囲で付け、勝手に発言内容を整え過ぎません。

漢字・ひらがな、英数字の全半角、単位、記号、固有名詞の表記ルールを決めます。装飾テロップでは短縮しても、字幕から重要条件を削らないよう、原文との差を台帳に残します。

## 9｜表示位置、色、画面との競合

字幕が顔、口元、手話、商品、操作ボタン、元からある画面文字を隠さないか確認します。背景が変化する動画では、単一場面だけでコントラストを判断しません。色だけで話者や重要度を区別せず、名前、記号、位置等を併用します。

焼き込み字幕は常に表示されますが、利用者が非表示や大きさ変更をできません。別トラック字幕は切替可能でも、プレイヤーの対応とファイル読込が必要です。目的と配信環境に応じて選び、可能なら両方の長短を検討します。

```text
字幕キュー【】と画面要素メモ【】を照合し、顔、口元、手話、商品、操作、既存文字を隠す区間を抽出。
位置変更、文短縮、背景処理、別トラック化の候補を出す。
```

## 10｜SRTの構造を検査する

SRTは一般に連番、開始と終了のタイムコード、本文、空行のまとまりで扱われます。付属見本は時・分・秒・ミリ秒を示し、小数部の区切りにカンマを使っています。対象ツールが求める文字コード、改行、時刻形式、マークアップは実際の仕様で確認します。

```text
SRT本文【】の連番、時刻形式、開始より後の終了、開始順、空行、重複、負の時刻、文字化け候補を検査。
形式検査と字幕内容の正しさを別々に報告する。
```

構文が正しくても、内容や同期が正しいとは限りません。逆に、編集ソフトが読み込めても別サービスで同じ見え方になる保証はありません。対象プレイヤーごとに読み込み、先頭・中間・末尾を確認します。

## 11｜WebVTTの構造を検査する

WebVTTはファイル先頭の`WEBVTT`ヘッダーと、時刻に対応したキューを持ちます。W3C仕様では、キューの終了時刻は開始時刻より後で、キューは開始時刻順に並びます。時刻の小数部はピリオドです。配置等の設定やマークアップもありますが、利用環境の対応を確認します。

```text
WebVTT本文【】のヘッダー、キュー開始・終了、開始順、空行、設定、許容マークアップ、文字方向を検査。
仕様上の構文と、対象ブラウザ・プレイヤーでの実表示を分けて報告する。
```

必要以上に位置を固定すると、小画面、拡大、異なる言語で不都合になることがあります。標準の挙動で問題がある時だけ設定を追加し、複数環境で確認します。

## 12｜トランスクリプトと視覚情報

字幕ファイルをそのまま連結しただけでは、読み物として不自然になったり、画面だけで示した情報が失われたりします。話者、見出し、段落、重要音、必要な視覚説明を整理したトランスクリプトを別成果物として作ります。

W3C WAIは、音声・映像の代替として字幕やトランスクリプトを挙げ、理解に重要な音や視覚情報を含めるよう案内しています。どの代替が必要かはコンテンツと適用する基準で確認します。

```text
確定字幕【】と画面説明【】からトランスクリプト案。
話者、段落、重要音、字幕だけでは伝わらない視覚情報を分け、推測した視覚情報は「要確認」とする。
```

## 13｜実再生と差分レビュー

字幕を動画またはプレイヤーへ読み込み、通常速度、必要なら速度変更、スマートフォン、PC等で確認します。先頭・中間・末尾だけでなく全編を再生します。字幕の早出し、遅れ、ちらつき、重なり、場面をまたぐ残留、文字化けを記録します。

修正後は、確定原稿、SRT、WebVTT、焼き込み版、トランスクリプトの差分を確認します。一つを直して他を直し忘れないよう、共通のキューIDまたは版番号を使います。公開用ファイルには言語と版を含む分かりやすい名前を付けます。

### 多言語版と文字コード

翻訳字幕は日本語版の単語を置き換えるだけでなく、対象言語の話者が意味、語調、固有名詞、単位、文化的前提を確認します。原語版と翻訳版でキューIDを対応させ、原文を直した時に翻訳版へ修正が伝わる台帳を作ります。言語ごとに文章の長さが変わるため、同じ改行と表示時間を機械的に流用しません。右から左へ書く言語や複数文字体系では、文字方向とフォント表示も対象環境で試します。

文字コードと改行コードが合わないと、内容が正しくても文字化けや読込失敗が起きます。元ファイルの符号化を記録し、変換前後で日本語、記号、アクセント文字を比較します。拡張子だけを変更して形式変換したことにせず、SRTとWebVTTそれぞれのヘッダー、時刻区切り、キュー構造を再検査します。

### 訂正履歴と公開後修正

公開後に誤字や同期ずれが見つかった場合は、元の誤り、影響するキュー、修正内容、根拠、確認者、公開反映日時を残します。重大な意味反転、氏名、金額、安全情報は、字幕だけでなく動画本体、説明文、トランスクリプトへの影響も確認します。配信先で字幕を差し替えられない場合は、公開停止や再アップロードを含めて判断します。

```text
旧版字幕【】と新版字幕【】をキューIDで比較し、内容、時刻、話者、重要音、形式の差分を表にする。
各差分に修正根拠、関連する翻訳版・焼き込み版・トランスクリプト、再公開の要否を付ける。
```

## 14｜よくある失敗と直し方

1. **自動字幕をそのまま公開**：全文を原音と照合する。
2. **否定が消える**：意味反転語を優先検査する。
3. **数字と単位が違う**：一次資料と話者へ確認する。
4. **固有名詞を推測**：公式表記一覧を作る。
5. **話者名を声で決める**：収録記録で確認する。
6. **重要音を全部消す**：理解に必要な音を残す。
7. **一画面の文字が多い**：意味単位へ分け表示時間を確保する。
8. **語句の途中で改行**：文法と意味で組み直す。
9. **字幕が顔を隠す**：画面要素に応じ位置を変える。
10. **色だけで話者を区別**：名前や記号を併用する。
11. **SRTとVTTの時刻を混同**：形式ごとに構文検査する。
12. **読込成功を品質合格とする**：内容・同期・表示を別に検査する。
13. **修正版が同期しない**：共通キューIDと版で差分管理する。
14. **字幕だけで代替完了と思う**：トランスクリプト・視覚説明の要否を確認する。
15. **全編再生しない**：完成ファイルと字幕を最後まで再生する。

## 15｜公開前チェック、公式情報、限界

- [ ] 原音と字幕を全編照合
- [ ] 数字・日付・単位・否定・条件
- [ ] 固有名詞・専門語・話者
- [ ] 理解に必要な重要音
- [ ] キュー開始・終了・重複・無字幕区間
- [ ] 改行・句読点・表記統一
- [ ] 顔・口元・手話・画面文字との競合
- [ ] SRT構文と対象プレイヤー読込
- [ ] WebVTT構文と対象ブラウザ読込
- [ ] トランスクリプト・視覚説明の要否
- [ ] 全編実再生と差分
- [ ] 版・言語・確認者・日付・未検証

確認した公式入口は[W3C WebVTT仕様](https://www.w3.org/TR/webvtt1/)、[W3C WAI「Captions/Subtitles」](https://www.w3.org/WAI/media/av/captions/)、[W3C WAI「Writing for Web Accessibility」](https://www.w3.org/WAI/tips/writing/)です（確認日：2026-10-23）。配信媒体・編集ソフトの仕様と適用するアクセシビリティ基準は利用時に再確認します。

本教材は架空原稿のみで、実音声、自動音声認識、話者分離、外部AI、翻訳、焼き込み、編集ソフト、ブラウザ・プレイヤーへの実読込、当事者・第三者テストを検証していません。完全な認識精度、法令・規格適合、すべての環境での表示を保証しない教材です。

## A/B/C/Dの役割と次の一歩

- **A｜無料体験**：数字・否定・固有名詞を校正する。
- **B｜完成見本**：SRT・WebVTT・校正台帳を読む。
- **C｜再利用できる道具**：校正シートと8プロンプトを使う。
- **D｜作り方講座**：素材保全から実再生まで判断する。

次は027「AIで動画の不要部分を自動カットする方法」。確定字幕と無音区間を手掛かりにしながら、意味・条件・安全情報を失わずにカット候補を検品する工程へ進みます。


## 権利と限界

他人の動画・音声の字幕を作るときは、元の動画の権利者の許可を確認します。字幕の文章を勝手に配布しません。本教材は、再生数・収益を保証しない教材です。
