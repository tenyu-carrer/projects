# 078-C｜AIで企業ブログを運用する 設計シートとプロンプト

**状態：再利用用初稿／検索エンジンの方針・使うサービスの規約は使う時点で公式ページを確認**

## 設計欄

- ブログの目的（1つ）：
- 読む人（どんな場面で、何に困っているか）：
- 書けるテーマの範囲（資格・経験がある分野）と、書かない分野：
- テーマの材料（お客さんの質問・現場の出来事など）の集め方：
- 公開の本数と曜日（続けられる数）：
- 書く人・確かめる人・公開する人：
- 1記事の型：
- 自社の経験・写真の載せ方（お客さんの許可）：
- AIを使う場所と、人が必ずやること：
- 事実（数字・制度・価格）の確かめ方：
- 記事の終わりの案内（相談・資料・関連記事）：
- 見直す日と見る数字（読まれた数・問い合わせ・検索の表示）：
- 確認者／確認日：

## プロンプト（この順で使います）

```text
私の会社【会社の説明】のブログの目的は【目的】、読む人は【読む人】です。お客さんから聞かれた質問【質問の一覧】から、ブログのテーマを20個作って。それぞれに、読む人が分かることを1文添えて、似ているテーマはまとめて。私の会社が答えられないテーマは入れないで。
```
```text
次のテーマ【一覧】から、3か月分（月【】本）の記事計画を作って。テーマ・読む人・元になった質問・公開日の目安を表にして。宣伝の記事（サービスの紹介）は全体の4分の1までにして。
```
```text
次のテーマ【テーマ】の記事の見出し構成を作って。順番は「結論→理由→自社の経験を入れる場所→注意すること→読んだ人の次の行動」。自社の経験を入れる場所は【ここに自社の経験】と空けておいて。
```
```text
次の見出し構成【構成】と、自社の経験のメモ【メモ】で、記事の下書きを作って。メモにない経験・数字・お客さんの声を作らないで。制度や価格の細かい数字は「公式ページで確認」と書いて。
```
```text
次の記事【記事】を、読む人【読む人】の立場で読んで、①分かりにくい所、②よくある一般論だけで、この会社らしさがない所、③根拠のない言い切り、④事実を確かめるべき所を、場所を示して表にして。文は書き換えないで。
```
```text
次の記事【記事】が、「検索順位のために書いた記事」ではなく「読む人のために書いた記事」になっているか点検して。読む人が知りたいことに答えているか、自社の経験や独自の情報があるか、読み終わって満足できるか、の3つの目で、足りない所を書いて。
```
```text
次の記事【記事】のタイトルと、検索結果に出る説明文（120文字前後）の案を3つずつ作って。記事に書いてあることだけを使い、大げさな言葉は使わないで。
```
```text
ブログを3か月運用しました。分かっていること【記事ごとの読まれた数・問い合わせ・検索の表示とクリック】をもとに、書き足す記事・直す記事・新しく書くテーマを表にして。数が少ないときは「まだ判断できない」と書いて。
```

AIは**テーマ出し・構成・下書き・点検**に使い、自社の経験・事実・公開の判断は人が行います。
