# 043-C｜X投稿 設計シートとプロンプト

**状態：再利用用初稿／投稿前に必ず全文を自分で読む**

## 設計欄

- アカウントのテーマ／読んでほしい人：
- 投稿の元になる素材（ブログ・動画・日々の気づき）：
- 1日の投稿数と時刻／返信や引用への対応の方針：
- 自動化の方法（公式の予約機能／APIの仕組み）と、その条件の確認日：
- 事実の確認のしかた／言い過ぎの基準：
- 確認者／確認日：

```text
ブログ記事【】から、Xの投稿を5本作って。1投稿1メッセージ、全角140字以内。記事のどの段落から取ったかを書き、記事にない数字は使わないで。
```
```text
投稿の下書き【】を、全角140字以内に縮めて3案。いちばん大事なことを1つだけ残して。
```
```text
投稿の下書き5本【】を点検して、同じ書き出し・同じ締め・同じハッシュタグが続いている所を指摘して、入れ替え案を出して。
```
```text
投稿の下書き【】の中で、事実の確認が必要な部分（数字・体験・サービスの機能・ニュース）を抜き出して、確認先の候補を付けて。
```
```text
長い話【】を、つながった複数の投稿（スレッド）に分けて。1本目だけで興味が持てるようにして、各投稿は140字以内に。
```
```text
もらった返信【】への返事を2案。相手の意見を受け止め、言い争いにならない言い方で。
```
```text
投稿の下書き【】が、ニュースや他人の発言を誤解させる言い方になっていないか点検して。元の情報と違う点を指摘して。
```
```text
1週間の反応【投稿ごとの表示・いいね・返信・リンクのクリック】から、届いた話題の傾向を整理して、次の週に1つだけ変えることを提案して。
```

短い文章ほど、言い過ぎや誤解が起きやすくなります。投稿前に、元の情報と照らし合わせます。
